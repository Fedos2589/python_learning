# Форматирование и линтинг: Ruff

## Что это и почему именно оно

В Python нет Prettier. Есть **Ruff** — он делает работу и Prettier, и ESLint
одновременно, одним бинарником, написанным на Rust.

| Твой фронтенд-стек | Python |
|--------------------|--------|
| Prettier | `ruff format` |
| ESLint | `ruff check` |
| `eslint --fix` | `ruff check --fix` |
| organize-imports | входит в `ruff check` (правило `I`) |
| `.prettierrc` + `.eslintrc` | секции `[tool.ruff.*]` в `pyproject.toml` |

Немного истории, чтобы понимать, почему всё так. До 2018 в Python спорили о стиле
как в JS до Prettier. Потом появился **Black** — форматтер с лозунгом
«настроек почти нет, смирись», и споры кончились. Black задал стандарт, включая
длину строки 88. В 2023 вышел Ruff — совместимый с Black по выводу, но в десятки
раз быстрее и с линтером внутри. Сейчас это дефолт в новых проектах.

Практический вывод: **не настраивай стиль под себя**. Весь Python-мир отформатирован
одинаково, и это его сильная сторона.

## Команды

```bash
uv run ruff format .          # отформатировать всё (= prettier --write)
uv run ruff format --check .  # проверить, не меняя (для CI)
uv run ruff check .           # найти проблемы (= eslint)
uv run ruff check --fix .     # починить то, что починимо автоматически
```

Точка на конце — «весь проект от текущей папки». Запускать из корня.

## В VS Code

Уже настроено в `.vscode/settings.json`: по `Cmd+S` файл форматируется, импорты
сортируются, автопочинимые замечания применяются. Руками команды дёргать почти
не придётся.

Одна деталь, которую я поправил в твоём файле: `editor.defaultFormatter` теперь
внутри блока `"[python]"`, а не глобально. Иначе VS Code пытался бы форматировать
Ruff-ом и Markdown, и JSON — а он умеет только Python.

## Что настроено и почему

Смотри комментарии прямо в `pyproject.toml` — там расписана каждая строка.
Главное:

- **line-length = 88** — стандарт Black, не трогаем
- **13 семейств правил** включено: от неиспользуемых импортов до ловушки с
  изменяемым аргументом по умолчанию (той самой из задачи 09 — теперь линтер
  поймает её за тебя)
- **`RUF001/002/003` выключены** — они ругаются на кириллицу в комментариях,
  подозревая опечатку в латинице. Нам это шум

## Проверь, что работает

Из корня проекта:

```bash
uv run ruff check .
```

Ruff найдёт ровно одно замечание — `I001` в `test_tasks.py`: между `import pytest`
и `from tasks import ...` стоит пустая строка, а они относятся к одной группе
импортов. Починится само:

```bash
uv run ruff check --fix .
```

Дальше должно быть `All checks passed!`.

Потом испорти любой файл специально — поставь лишние пробелы, кривые отступы,
одинарные кавычки, длинную строку — и нажми `Cmd+S`. Всё должно встать на место.
