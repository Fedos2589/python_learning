## 1. Реальный баг: `add_item` (задача 09)

```python
if not basket:
    return [item]
```

Тесты это пропустили, но баг есть. `not basket` истинно для **двух разных**
случаев: корзину не передали (`None`) и передали пустую (`[]`). Во втором
случае функция возвращает **новый** список, а список вызывающего остаётся
пустым:

```python
basket = []
add_item("a", basket)   # -> ['a']
print(basket)           # -> []   ← а ожидали ['a']
```

Это ровно та ошибка, от которой защищает правило «для `None` всегда `is None`».
`not x` спрашивает «пустое ли?», `x is None` — «есть ли вообще?». Это разные
вопросы.

```python
if basket is None:
    basket = []
basket.append(item)
return basket
```

Я добавил в `test_tasks.py` тест `test_add_item_mutates_explicitly_passed_empty_basket`
— он сейчас красный. Сделай его зелёным.

Заодно: в README недели 1 написано `items = items or []` — **та же ошибка**.
`or` срабатывает на любом ложном значении. Правильный идиом —
`if items is None`. Формулировку в README я поправил.

## 2. Срезы не бросают исключений — значит, охрана лишняя

`middle_elements`:

```python
le = len(items)
if le < 3:
    return []
return items[1:-1]
```

Проверь в REPL:

```python
[1, 2][1:-1]   # []
[1][1:-1]      # []
[][1:-1]       # []
```

Срез сам возвращает пустой список. Тело функции — одна строка:

```python
return items[1:-1]
```

Это и есть пункт «срезы не бросают ошибок» из README, применённый на практике.
В JS ты бы писал такую охрану — здесь она шум. Плюс переменная `le` используется
один раз: даже если бы проверка была нужна, `if len(items) < 3` читается лучше.

## 3. То же самое в `count_words`

```python
if not text:
    return 0
return len(text.strip().split())
```

`"".strip().split()` → `[]` → `len` → `0`. Первые две строки не нужны:

```python
return len(text.split())
```

`.strip()` тоже избыточен: `split()` без аргументов сам съедает пробелы по краям
и склеивает подряд идущие. Проверь: `"  a   b  ".split()` → `['a', 'b']`.
Это же относится и к `slugify` — там `.strip()` можно убрать, `.split()` уже всё
сделал. (В `slugify` остальное — хорошо: цепочка `lower().split()` + `join` это
идиоматично.)

## 4. `else` после `return` — лишний уровень вложенности

`second_largest`, `build_url`, `add_item`:

```python
if len(unique_sorted) < 2:
    return None
else:
    return unique_sorted[-2]
```

Если ветка с `if` заканчивается `return`, всё после неё уже недостижимо для
этого случая. `else` не добавляет информации, но добавляет отступ:

```python
if len(unique_sorted) < 2:
    return None
return unique_sorted[-2]
```

Это называется guard clause — «сначала отсекаем исключительные случаи, потом
основная логика на нулевом уровне вложенности». В `describe_flag` цепочка
`if / elif / else` наоборот уместна: там три равноправных случая, а не один
особый.

## 5. `first_non_empty` — неявный `return None`

```python
for value in values:
    if value:
        return value
# ← сюда падаем, если ничего не нашли
```

Работает: Python возвращает `None` из функции, дошедшей до конца. Но подпись
обещает `object | None`, а из кода этого не видно — читатель должен догадаться,
что автор так и хотел, а не забыл строку. `mypy --strict` ругается прямо:
`Missing return statement`. Допиши явно:

```python
for value in values:
    if value:
        return value
return None
```

Правило: если функция иногда возвращает значение, она должна возвращать
значение **везде** — явно.

## 6. `word_frequency` — работает, но в стандартной библиотеке это уже есть

Твоя реализация через `dict.get(word, 0) + 1` — правильный идиом, и его нужно
уметь писать руками. Знай, что в проде пишут так:

```python
from collections import Counter

def word_frequency(text: str) -> dict[str, int]:
    return dict(Counter(text.lower().split()))
```

`collections` — это модуль, который стоит пролистать целиком: `Counter`,
`defaultdict`, `deque`. Аналогов в стандартном JS нет, и на собесе про них
спрашивают.

Ещё: `frequency = {}` — `mypy --strict` не может вывести тип пустого словаря.
На неделе 6–7, когда включим strict, это станет ошибкой. Пишут так:
`frequency: dict[str, int] = {}`.

## 7. `get_nested` — двойной поиск по ключу

```python
if isinstance(current, dict) and key in current:
    current = current[key]
```

`key in current` и `current[key]` — два прохода по хеш-таблице. Питоничнее —
сентинел-объект:

```python
_MISSING = object()

current = data
for key in keys:
    if not isinstance(current, dict):
        return default
    current = current.get(key, _MISSING)
    if current is _MISSING:
        return default
return current
```

Зачем `object()`, а не `None`: `None` — легальное значение в словаре.
`{'a': None}` с `.get('a', None)` не отличить от отсутствующего ключа. Уникальный
объект-маркер отличить можно — через `is`, потому что он равен только себе.
Это тот же приём, что sentinel в TypeScript, только без типов.

Это уже не про синтаксис, а про мышление — если сейчас тяжело, вернись к пункту
на неделе 5.

## Один общий вывод

Все шесть замечаний — про одно: **в Python пустое и отсутствующее это разные
вещи, и язык уже умеет обрабатывать крайние случаи сам**. `not x` вместо
`is None`, охрана перед срезом, `if not text` перед `split()` — это привычка
из JS, где `arr[10]` даёт `undefined`, а `null == undefined` истинно, и защищаться
приходится вручную. Здесь — не приходится. Заметишь эту привычку у себя ещё раз
на неделе 2, в comprehensions: тянуть будет написать цикл с `if`, а нужен фильтр
внутри выражения.
