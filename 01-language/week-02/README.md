## Главная идея недели

На прошлой неделе почти в каждой задаче ты писал одно и то же:

```python
result = []
for item in items:
    result.append(do_something(item))
return result
```

Это правильный цикл, но в Python для него есть выражение:

```python
return [do_something(item) for item in items]
```

Читается наоборот по сравнению с `items.map(...)` из JS: сначала что делаем,
потом откуда берём. Первые дни будет ощущаться вывернуто наизнанку — это
нормально, привыкается за неделю.

Но comprehension — не универсальная замена циклу. Он **всегда обходит всё** и
**всегда строит новый список целиком**. Если нужен первый подходящий элемент —
нужны круглые скобки вместо квадратных, и это уже генераторное выражение,
которое считает по одному. Задачи 12 и 15 про эту разницу; в тестах есть
бесконечная последовательность, на которой список-comprehension просто повесит
тест.

## Грабли этой недели

- **Порядок `for` во вложенном comprehension** — как во вложенном цикле:
  внешний первым. Наоборот — `NameError`.
- **`zip` молча обрезает** по короткой последовательности. Никакой ошибки,
  просто часть данных исчезает. В Python 3.10+ есть `zip(..., strict=True)`,
  который ругается на разную длину — знать про него полезно.
- **Кортеж — не список.** Неизменяем, но распаковывается. Возврат нескольких
  значений в Python — это кортеж, а не объект, как в JS.
- **`{**a, **b}` создаёт новый словарь**, а `a.update(b)` меняет `a` на месте.
  Второе испортит аргумент вызывающего — та же ошибка, что была с корзиной.
- **Генератор одноразовый.** Пройти по нему дважды нельзя: второй проход даёт
  пустоту. Именно поэтому в проекте между парсингом и статистикой стоит
  `list(...)`, и это осознанное решение, а не забытая оптимизация.

## Проект: парсер CSV-лога

Три модуля, у каждого своя ответственность:

```
parser/
  parsing.py   разбор текста в структуры       (задачи 1–3)
  stats.py     вычисления по структурам        (задачи 4–9)
  report.py    сборка текстового отчёта        (задача 10)
  access-log.csv   данные: 20 годных строк, 3 битые
```

Библиотекой `csv` пользоваться нельзя — весь смысл в том, чтобы разобрать формат
руками. Когда доделаешь, отчёт можно посмотреть глазами:

```bash
uv run python 01-language/week-02/parser/report.py 01-language/week-02/parser/access-log.csv
```

Почему именно такое деление: `parsing` ничего не знает про статистику, `stats`
ничего не знает про текст и файлы, `report` ничего не вычисляет сам. Каждый
модуль можно тестировать в одиночку — и тесты именно так и написаны, в трёх
файлах. Ровно по этому принципу на этапе 3 будет разрезан FastAPI-проект, только
слои будут называться иначе.

Задача 10 намеренно оставлена без импортов из `stats` — допишешь сам, когда
поймёшь, какие функции тебе нужны. Это и есть тема «модули»: импортируем то, что
используем, и ничего лишнего.
